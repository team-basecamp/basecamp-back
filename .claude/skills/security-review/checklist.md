# 보안 점검 체크리스트

## 인증 / 인가
- [ ] 보호가 필요한 엔드포인트에 인증이 걸려 있는가 (SecurityConfig의 permitAll 범위 확인).
- [ ] 리소스 소유자 검증이 있는가 (남의 예약/결제/회원 정보 접근 차단).
- [ ] JWT 서명·만료·issuer 검증이 실제로 수행되는가.

## 입력 검증
- [ ] 모든 요청 DTO에 Bean Validation이 적용되고 `@Valid`로 검증되는가.
- [ ] 경로/쿼리 파라미터 범위·형식 검증이 있는가.

## 인젝션 / 데이터 접근
- [ ] JPQL/네이티브 쿼리에서 문자열 결합 대신 파라미터 바인딩을 쓰는가.
- [ ] 응답 DTO가 필요한 필드만 노출하는가 (엔티티 전체 직렬화 금지).

## 시크릿 / 설정
- [ ] 하드코딩된 비밀번호·API 키·토큰이 없는가.
- [ ] 시크릿이 `application-secret.yml`/`.env`로 분리되어 커밋 대상에서 제외되는가.
- [ ] 로그에 토큰·개인정보·전화번호가 찍히지 않는가.

## 도메인 특화
- [ ] 결제 금액·상품이 서버에서 재검증되는가 (클라이언트 값 신뢰 금지).
- [ ] 예약/결제에 멱등성 또는 중복 방지 로직이 있는가.
- [ ] 에러 응답에 스택트레이스·내부 경로가 노출되지 않는가.
